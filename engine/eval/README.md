# 记忆检索评测集

量化 `recall` 检索质量的尺子。改任何与检索相关的东西（分词、打分、弃权判据、过滤维度）之前
先跑一遍拿到基线，改完再跑一遍对比——**别凭感觉判断"好像变准了"**。

## 为什么要新建这套东西

项目原有的唯一检索评测是 `engine/examples/tuning/questions/replay.rs` 的 REPLAY-01/02，
但它**是废的**：其构造是 `EventKind::Query { query: m.cue.clone() }`——
query 就是被检索记忆自己的 cue 全文，属于退化自查询，任何检索器都近乎满分。
历史基线 `recall_rate=100%` 是这个原因，**不代表现有检索很好**。
拿它当"新方案没提升"的证据是错的。

## 文件

| 文件 | 说明 |
|---|---|
| `corpus.json` | 真实记忆库快照（261 条可召回记忆），评测的语料底座 |
| `memory-golden.jsonl` | **50 道 golden 题**，由 `build_golden.py` 生成，冻结进版本库 |
| `noise-queries.txt` | 50 条纯噪声 query，标定弃权判据用 |
| `build_golden.py` | 题源 + 生成器 + 出题质量自查 |
| `score.py` | 主评测：现状词法 vs BM25 对拍，**分 kind 报告** |
| `verify_rust.py` | 用**真实 Rust 二进制**跑评测（绕开所有 Python 复刻代码） |
| `calibrate.py` / `abstain2.py` / `abstain3.py` / `portability.py` | 弃权判据的标定与可移植性验证 |

`*-report.txt` 是每次跑出来的报告，已 gitignore。

## 题型配比与为什么这么分

| kind | 数量 | 是什么 |
|---|---|---|
| `explicit` | 15 | query 用了 cue 里的原词。**基线题型，检验不要变差** |
| `paraphrase` | 20 | 同义改写，刻意不用 cue 原词。**主战场** |
| `prescriptive` | 10 | **prompt 描述任务、记忆描述失败**（"我要发版" → 发版铁律那条） |
| `implicit` | 5 | 需要跨条关联 |

`prescriptive` 是这套题库最重要的发明：对一个最高价值内容是"踩过的坑"的记忆系统，
**它才是唯一能量化"该想起的时候想起来"的题型**。前三种题型量的都是"我知道要找什么时能不能找到"，
而真实场景里最贵的失败是"我压根不知道有这条记忆存在"。

**必须分 kind 报告，不要只看总平均**——15 道 explicit 两个检索器都满分，会把
paraphrase 的差距摊薄一半。

## 先准备本地数据（仓库里没有，也不该有）

本仓库是 **public**，而评测要用的语料就是**你自己的记忆库**——里面有服务器地址、
账号、内部决策这类东西。所以仓库里只放**方法与工具**，数据一律留本地
（见 `.gitignore`）。跑之前需要自备三份：

| 文件 | 怎么来 | 说明 |
|---|---|---|
| `corpus.json` | `python _mkcorpus.py` | 从本机记忆库导出的语料快照 |
| `golden-src.txt` | 自己写 | 题源，格式 `id \| kind \| query \| gold 定位子串`，见下方出题纪律 |
| `writeside-patches.txt` | 自己写 | 仅 `writeside_probe.py` 需要，格式 `cue 定位子串 \| 现象侧措辞` |

库路径都可用环境变量覆盖，不必改脚本：
`ENGRAM_GENERAL_DB` / `ENGRAM_PROJECT_DB`（`name=path` 形式）/ `ENGRAM_KB_BIN`。

## 用法

```bash
python build_golden.py            # 改了题源后重新生成题库（含出题质量自查）
python score.py --abstain --detail  # 离线对拍（Python 复刻的分词与打分）
python verify_rust.py             # 用真实 Rust 二进制跑，需要先 cargo build --release
```

## 出题纪律（违反就是自欺）

1. **先想"用户会怎么问"再定 gold**，绝不跑一次检索拿返回值当 gold——那是给现状背书。
2. gold 用 **cue 里的独特子串**定位，由脚本解析成完整 id。不要手抄 mem id：
   库里短 id 前缀（前 8 位 hex）**有重复**（`18cdbfff` / `18ce0171` / `18ce017d` /
   `18cdc386` / `18cdc38b` / `18cddf8d` 各有两条），抄错了整把尺子会**静默失真且不报错**。
   `build_golden.py` 对定位子串做唯一性校验，命中 0 条或多条都会当场失败。
3. `paraphrase` 题要真的换词。`build_golden.py` 会算 query 与 gold cue 的词元重叠，
   并标出其中判别力强（IDF > 4）的重叠词——那是出题时泄漏了原词的信号。

## 已经量过的路线（别再重走）

2026-08-22 用这套尺子把「怎么让记忆更好查」的各条路线逐个量了一遍。
**结论全部有本地实测支撑，不是引用论文**：

| 路线 | 脚本 | 结果 | 判决 |
|---|---|---|---|
| BM25 换掉子串匹配 | `score.py` / `verify_rust.py` | paraphrase +43%、prescriptive +37%、噪声弃权 18%→82% | ✅ **已实现** |
| 向量语义检索（kb sidecar） | `vector_probe.py` | hit@3 **+0pp**、MRR −0.001 | ❌ 砍掉 |
| 图谱关联跳转（PPR 扩散） | `graph_probe.py` | MRR **−0.001**，implicit +0.002 | ❌ 不做 |
| 补 unigram 单字词元 | `unigram_probe.py` | MRR +0.023，但噪声弃权 **82%→50%** | ❌ 不划算 |
| 打分调参（字段加权 / RM3 等） | `diagnose.py` | 未命中题 **100% 是硬鸿沟**，没有共同词可调 | ❌ 结构上无效 |
| 写入端补现象侧措辞 | `writeside_probe.py` | MRR 0.600→0.826（**上限，见下方局限**） | ✅ 已写进 reviewer-prompt |

### 几条踩过的坑

- **向量那条推翻过一次结论**：此前一份 **12 题**调研说 hybrid 比 BM25 高 25pp，据此把向量写进了路线图。
  50 题重测是 +0pp——12 题里一题就值 8pp，噪声大过信号。**检索类结论至少 50 题，且必须分 kind 报告。**
- **图谱失效的本地原因**：261 个节点连出 5810 条边、平均度数 43、孤立点 0——图几乎全连通。
  库里记忆主题高度同质（大量「engram 复盘者」「Windows 坑」），共享词元太多，图没有结构，
  扩散等于给所有人平均加分。图谱要有用，前提是图**稀疏且有社群**。
- **`unigram_probe.py` 的判定逻辑有过缺陷**：它只检查了 explicit 不劣化与误弃不增，
  漏掉噪声弃权率，于是把「弃权率腰斩」的配置判成了「值得做」。
  **改判据时记得同时盯收益侧和代价侧两组指标。**

### `writeside_probe.py` 的局限（读它的数字前必看）

那个 +0.226 是**机制上限，不是期望收益**：补充文本是**看过 query 之后**写的，
脚本自查显示平均重叠 4.8 个词元（I-01 高达 16 个，基本是照抄）。
「12/12 全部救回且全排第一」这个结果本身就是过拟合的信号。

它能证明的：**补现象侧措辞可以跨越硬鸿沟，这条路通**。
它不能证明：随便补都有这个幅度。
真实幅度要用「写的时候不知道未来会被怎么问」的记忆去验证——
即 `reviewer-prompt.md` 里那条写入端干预对**新**记忆的效果，需要真实使用数据。

**因此不建议现在批量改写存量记忆**：收益无法验证，还有污染语料底座的风险。

## 当前基线（2026-08-22，真实 Rust 二进制实测）

| 检索器 | explicit | paraphrase | prescriptive | implicit | 合计 MRR | 噪声弃权率 |
|---|---|---|---|---|---|---|
| 现状词法 `--lexical-legacy` | 1.000 | 0.219 | 0.510 | 0.253 | 0.515 | 18% |
| **BM25（默认）** | 1.000 | **0.313** | **0.700** | 0.325 | **0.598** | **82%** |

要点：`explicit` 两者都满分（新打分器没让原本查得到的变差），
提升全部来自 `paraphrase`(+43%) 与 `prescriptive`(+37%)。

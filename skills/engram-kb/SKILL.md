# engram-kb 知识库使用规则

engram-kb 是 engram 的**本地知识库（RAG）sidecar**：把成批文档分块、向量化存进本地
LanceDB，之后用中文语义 + 全文混合检索。它是**可选组件**（独立二进制，按需下载），
普通用户从不碰命令——本 Skill 是它的「判定大脑」，教你（AI）在对的时机替用户**自动**
完成安装 / 入库 / 检索。

> 二进制实现见 `engram/docs/知识库设计文档.md`。本文件只讲「AI 该怎么用」。

---

## 0. 最重要：知识库 vs engram 记忆，什么进哪个

你的环境里有两套「记东西」的机制，**先分清再动手**：

| | engram 记忆 | engram-kb 知识库 |
|---|---|---|
| 存什么 | **对项目 / 资料的提炼认知**：决策、进度、踩坑、偏好、心智地图 | **现成文档资料的原文**：设计文档、API 手册、产品资料、会议纪要、规范、手册 |
| 形态 | 一句话 cue + 指针（人脑式补集） | 文档切块后的原文 + 向量 |
| 怎么用 | hook 自动注入热索引；`engram write/recall` | 本 Skill：`engram-kb ingest/search` |

**判断口诀**：
- 用户给来一份 / 一批**现成、完整的文档资料** → **知识库**（照存原文供检索）。
- 用户表达一个**需要记住的事实 / 结论 / 决定**（「记住我们用 X 架构」「我喜欢 Y」）→
  **engram 记忆**（按 engram skill 提炼成 cue）。

**两条别犯的错**：① 别把知识库文档的内容再提炼一遍写进 engram（重复、浪费）；
② 别把零散的对话结论塞进知识库（那是 engram 的活，知识库只收成形文档）。

## 1. 前提：每次操作前先确保 sidecar 就绪

知识库二进制不在插件包里、首次用要下载。**任何 ingest/search/list 之前**，先定位并检测：

```bash
PLUGIN="${CLAUDE_PLUGIN_ROOT:-$(ls -1d "${CLAUDE_CONFIG_DIR:-$HOME/.claude}"/plugins/cache/*/engram/*/ 2>/dev/null | sort -V | tail -1)}"
bash "$PLUGIN/scripts/ensure-kb.sh" --check-only
```

- 输出 `KB_BIN=<路径>` → 就绪，**记下这个路径**，后续命令都用它（每次 Bash 调用是
  独立 shell，变量不跨调用保持——把路径替进命令再执行）。
- 输出 `KB_MISSING=1` → 还没装，进 §2 安装流程。
- 输出 `ENGRAM_KB_PLUGIN_NOT_FOUND` 或定位失败 → 告知用户插件目录没找到，停止。

---

## 2. 安装 / 初始化（用户说「装知识库」就自动办）

**触发**：用户说「装 / 启用 / 开启知识库」「我想用知识库功能」「把知识库搭起来」；
或在 §3 入库时发现 sidecar 还没装。

**流程**（普通用户全程只需点头同意，不碰命令）：
1. 跑 §1 的 `ensure-kb.sh --check-only`；
2. 若 `KB_MISSING=1` → **先停下告诉用户**：「启用知识库需要下载约 60–80MB 的组件
   （`KB_SIZE_HINT` 里的体积说明原样转告），首次用一次，之后离线可用，要装吗？」
3. 用户同意 → 执行下载：
   ```bash
   PLUGIN="${CLAUDE_PLUGIN_ROOT:-$(ls -1d "${CLAUDE_CONFIG_DIR:-$HOME/.claude}"/plugins/cache/*/engram/*/ 2>/dev/null | sort -V | tail -1)}"
   bash "$PLUGIN/scripts/ensure-kb.sh"
   ```
   输出 `KB_BIN=<路径>` 即装好。下载失败时把 stderr 的中文错误原样转告，不重试超过一次。
4. （可选）问用户要不要**顺便预下载嵌入模型**（约 95MB，国内可先
   `export HF_ENDPOINT=https://hf-mirror.com`）：`"<KB_BIN>" ensure-model`。不预下也行，
   首次 ingest/search 会自动下，但那次会多等十几秒。
5. 告诉用户「知识库已就绪，把文档或目录给我就能建库，以后直接问我里面的内容」。

---

## 3. 入库（含：给成批文档就主动建议）

**显式触发**：用户说「把这些文档存起来 / 建知识库 / 索引这些资料 / 以后好查」。

**主动触发（重要）**：用户**给来成批参考资料**——哪怕没明说入库——你要**主动建议**。
识别「成批参考资料」：给了一个 `docs/` 目录、多个文档文件、或用户说「这是我们
产品 / 项目的资料 / 文档 / 手册 / 规范」。这时主动问一句：
> 「这些资料我可以索引进知识库，以后你直接问、我语义检索着回答，要建吗？」

**做法**：
1. 确保 sidecar 就绪（§1，没装则走 §2）；
2. 入库（自动增量，未变的文档跳过、不重算嵌入）：
   ```bash
   "<KB_BIN>" ingest --json <文件或目录>...
   ```
   - 默认收 `.md` / `.txt`，要别的后缀加 `--ext md,txt,pdf` 之类；
   - 首次会自动下嵌入模型（约 95MB），stderr 有提示，属预期，转告即可；
3. 告知结果（入库 N 篇、M 个 chunk）+ 「以后直接问我里面的内容」。

**别做**：单条事实 / 结论 / 一句话决定**不要**走知识库（那是 engram 记忆，见 §0）。

---

## 4. 检索（信息型问题主动查，不必等用户开口）

**触发**：用户问的问题，答案可能在已入库文档里——典型如「X 是怎么设计 / 规定 /
实现的」「关于 Y，文档里怎么说」「我们的 Z 流程是什么」。**会话开始注入的知识库概览**
（SessionStart hook 给的「本项目知识库含 N 篇文档…」）告诉你本项目有哪些文档，据此
判断该不该查——**相关就主动查，不用用户明说「去知识库里找」**。

**做法**：
1. 确保 sidecar 就绪（§1）；
2. 语义 + 全文混合检索：
   ```bash
   "<KB_BIN>" search --json --query "<把用户问题转成检索词>" --limit 8
   ```
   - JSON 里每条 `hit` 的 `text` 是**完整 chunk 原文**（不像 text 模式截断）；
   - 要限定某文档：`--filter "doc_path = 'docs/xxx.md'"`（SQL 谓词）；
3. **顺命中的 `doc_path` + `breadcrumb`（章节面包屑）读原文**拿完整上下文——命中片段
   只是线索，别只凭片段下结论；
4. 回答时**带出处**（哪篇文档的哪个章节），方便用户核对。

**分数解读**（`score` 是 RRF 融合分，不是相似度）：≈0.033 = 该片段在向量与全文两路
检索中**都排第一**（强共识，最可信）；≈0.016 = 只在单路上榜；分数出现断崖
（0.033→0.016）说明断崖之前的结果可信度高。

## 5. 命令速查

所有命令用 §1 拿到的 `<KB_BIN>` 绝对路径；知识库目录**自动锚定**当前项目
（向上找 `.engram/`），无需传 `--db`。`--json` 给结构化输出供你解析。

| 命令 | 用途 |
|---|---|
| `ingest <路径>... [--ext md,txt] [--force]` | 入库 / 增量更新（目录递归） |
| `search --query "..." [--limit 8] [--filter SQL]` | 混合检索（向量 + 全文，RRF 融合） |
| `list` | 已入库文档清单 |
| `remove --doc "<doc_path>"` | 删某文档全部 chunk（doc_path 须与 list 一致） |
| `status` | 文档数 / chunk 数 / 模型就绪状态 |
| `ensure-model` | 预下载 / 校验嵌入模型 |

> 程序员也可直接用 `/engram:kb` slash command 或裸 CLI——那是同一套二进制的快捷入口，
> 与本 Skill 走的是同一份数据。

# engram 记忆系统使用规则

engram 是仿人脑的分层记忆系统：**总结当索引、按需回溯细节、遗忘=降级不删**。
本 Skill 是它的"判定大脑"——引擎（`engram` 二进制）只做机械的存取与升降级，**何时检索、写什么、判定真使用**这些判断都依本规则执行。

> 设计全貌见 `engram/docs/设计文档.md`。本文件只讲"怎么用"。

---

## 0. 作用域与库怎么定（`.engram/` 锚点）

记忆分两种库：
- **公共库**：用户级共享 L1-3，恒定加载，在 `~/.engram/general.redb`。
- **项目库**：每个项目根下的 `<项目>/.engram/engram.redb`，存该项目的 L4。

**当前是哪个项目，由「`.engram/` 锚点」决定，不靠 cwd**：引擎从当前目录**向上找最近的 `.engram/`**——
- 找到普通项目锚（`.engram/` 有库、无 `workspace` 标记）→ 那个目录即项目根；
- 找到**项目管理目录**锚（`.engram/workspace` 标记，由 `/engram:root`（即 `engram root` 命令）所建）→ 项目根 = 该管理目录的**直接子目录**（你正处的那一支）；
- 一路无锚点 → 当前目录即项目根。

所以同一项目在 `src/`、`plugin/` 等任意子目录开会话，都锚定到**同一个项目库**，不再碎片化（旧的「cwd 当 root + 猜活跃子项目」已废弃）。

**怎么拿当前作用域**（手动跑 list/recall/write 前先来一次）：
```
engram resolve --format json   # 输出 general_db / project_db / project_name / kind
```
之后各命令统一带 `--general-db <general_db> --project-db <project_name>=<project_db>`。`kind` 为 `workspace` 表示你正站在项目管理目录本身（特殊，见 §1.5）。

> 宿主 hook（Claude Code 为 SessionStart / UserPromptSubmit）已按锚点自动注入热索引；只有你**手动**跑 list/recall/write 时才需先 resolve。

## 1. 会话中：怎么用记忆（主 agent）

### 读
- 热索引由 hook 在会话开始与每次提问前自动注入（你已能在上下文里看到 L1/L2 与各活跃项目 L4.1/L4.2 的正文）。**先读它**。**常驻的只有这四层**——**L3 普通层与 L4.3 项目普通层不常驻**，热索引末尾只给它们一行「按需层」目录（条数 + 高频主题词），内容要靠 `recall` 显式取（见下）。每行行首的 `#<id首段>`（如 `#18beb926f903e300`）是该条记忆的短标记，供会话末复盘者把「真影响了输出」的记忆映射回 id 加固——你读记忆时可忽略它。
- **被问"这个项目是什么 / 还有哪些待做 / 进度到哪 / 以前是否处理过 X"这类问题——先查记忆、别先翻代码**：热索引里的 **L4.2**（定位 / 架构地图 / 已定型决策）常已有答案；但"还剩什么 / 进度到哪"多落在 **L4.3**（快衰减层，短期开口 / 当前进度类记忆多自然落这里），而 **L4.3 不在热索引里**——**必须先 `recall` 一次**（`--query "开口 进度 下一步"`，中文查询要空格分词）；**仍不够才扫代码**。代码是细节 ground truth，但"还剩什么、为什么这么做、否过什么"这类**意图 / 进度问题，记忆才是第一信源**。
- 需要某条记忆的细节时：**顺着它的指针（`file:line` / doc / url）去查 ground truth**，而不是凭印象。指针就是为"验证而非重建"准备的。
- 想找**没在热索引里**的东西——**L3 / L4.3 的全部内容**（它们不常驻）、以及已冷掉的旧事（"我们以前是不是处理过 X"）：
  ```
  engram recall --general-db G [--project-db n=p ...] --query "关键词 关键词" [--limit 10]
  ```
  recall 默认连冷库一起搜，返回候选（id/层级/状态/score/eff/cue/指针）。**查询是对 cue + tags 的词法匹配，中文必须空格分词**（写 `"engram 热索引 预算"`，别写成一整串），多给几个同义词能明显提高命中。**拿到候选后由你（LLM）做语义判断**挑出真正相关的，再顺指针取细节。

### 写
- **不要在干活时随手写记忆**（污染上下文、费 token）。写入集中在会话末的巩固阶段（见 §3）。
- 唯一例外：用户**显式要求**"记住 X"——这是 §2 的 override 门，可当场 `write`。

## 1.5 在「项目管理目录」里怎么办

`engram resolve` 的 `kind` 若为 `workspace`，说明你**正站在项目管理目录本身**。用户常在这里聊天、调研、酝酿还没建目录的项目——**管理库就是这些谈话内容的家**。它**不是通用层**：一台电脑会有多个管理目录，各自的谈话各归各的库；公共 L1-3 只收真正跨项目的东西。

- **谈话内容**（话题、调研、还没建目录的项目讨论、留下的开口）→ 写**管理库**，**按各自重要度落层**：短命话题 importance 低、自然落快衰减的 L4.3，值得长期留的话题结论按重要度落 L4.2。**别因为"话题与管理目录无关"就推到公共 L1-3**——谈话内容默认就落管理库。
- **管理元信息**（这批项目的统一规范、哪个项目负责什么）→ 管理库 L4.2。
- **要动手做具体项目了** → **主动在它下面建一个项目子目录**（按项目内容起名，拿不准就先问用户一句），进到那个子目录里干活；从此该项目的具体信息写**它自己的项目库**（`resolve` 在子目录会自动锚定到它），不再写管理库。先前落在管理库的同话题谈话记忆，可顺手迁入项目库（项目库 write + 管理库 supersede）。
- **别把已建目录项目的细节写进管理库**——那是项目库的活。

SessionStart hook 注入热索引时，也会在前言提醒你"当前在项目管理目录"。

## 2. 写什么 + 落哪层：salience 判定

分四步走：**①可恢复性闸门**（值不值得写）→ **②作用域闸门**（进公共层还是项目 L4）→ **③显著度**（importance 高低 / 落哪层）→ **④敏感信息闸门**（凭据只记指针）。外加一个 override（只管"写不写"）。

### ① 可恢复性闸门（写不写）
能从代码/文档/git 里 grep 出来吗？**能 → 不写**（细节留在 artifact 里，记忆只存它的补集）。不能（意图 / 为什么 / 被否的方案 / 当前进度 / 死路）→ 才有资格写。

### ② 作用域闸门（公共层 vs 项目 L4）——**默认 L4**
先问：这条**只在当前这个项目/仓库里成立**，还是**换个项目也照样成立**？
- 只在本项目成立（本仓库的架构、约定、踩过的坑、某处为何这么写）→ 写**项目 L4**（带 `--project NAME`，NAME = `engram resolve` 给的 `project_name`）。**这是默认去向。**
- 跨项目通用（用户身份/称呼/长期偏好、与具体仓库无关的工具用法或普适事实）→ 才升到**公共 L1-3**。

> 偏置很重要：**身处项目时默认 L4**，只有明确判断"拿到别的项目也有用"才进公共层。否则公共层会被单个项目的细节噪声污染，换项目后满眼无关记忆。
>
> **作用域是管理目录（kind=workspace）时同理**：谈话内容默认落**管理库**（按重要度落层，见 §1.5），不因"与管理目录这个'仓库'无关"而升公共层——管理库不是通用层，公共 L1-3 只收真正跨项目的偏好与普适事实。

### ③ 显著度（importance 高低 / 落哪层）
- **【+】意外度**：推翻了默认假设 / 文档所述 / 既有认知（"该 API 实际返回 X 而非文档写的 Y"）。
- **【+】被纠正/重复次数**：用户为同一件事纠正第二次 → 重要且易忘。
- **【+】强调/命令强度**："记住""千万别""永远""重要"、祈使句。
- **【+】决策/承诺**：在若干方案里做了选择、立了承诺（artifact 只记"是什么"，不记"为什么选它、否了谁"）。

> **层级不绑定内容类型**：落哪层只由**重要度与时效性**决定——开口 / 谈话内容等任何内容都按各自重要度落层，没有"某类内容只能进某层"的规定（短命的进度开口通常 importance 低、自然落快衰减层；重要的长期开口按其重要度落更高层）。

### ④ 敏感信息闸门（凭据只记指针）
凡**密钥 / token / 密码 / 连接串**形态的值，一律**不写值本身，只写指针**——如「密钥在 `.env` 的 X 项」「见某某文档」。用户显式说"记住某凭据"时也一样：记住它**存在哪**，不记它**是什么**（下方 override 只保证"写入"，不豁免本闸门）。

### 项目记忆该覆盖哪几类（按 L4 子层）
L4 别只记"踩坑/纠错"。每个项目应主动沉淀下面几类——都是散落 artifact 的**补集（综合 / 提炼，单条 grep 拿不到）**，是新会话快速进入状态、避免重复劳动的关键（故能过 ① 闸门）。**铁律：能从单文件 grep / `ls` 直接拿到的（目录树、配置项、CLAUDE.md 里的规则原文）不存——只存提炼出的心智模型。**

**L4.1 项目潜意识层 —— 铁律（极难忘，类比 L1，importance 0.7~0.9）**
- **项目铁律 / 不可违反的约定**：本项目必须**始终遵守**的硬规则、绝对禁忌、必守流程（如"绝不直接 push main""动这块前先读设计文档""所有 public fn 必须有 rustdoc"）。
- **怎么来**：① 用户对本项目的显式"永远 / 绝不"指令；② 被反复纠正后确立的隐性约定。**不要扫描项目去抽规则、也不要照抄 CLAUDE.md / README / lint 配置里的规则**——那些是 artifact、会被自动加载、能 grep，过不了 ① 闸门；L4.1 只存它们**没写、却踩出来**的隐性铁律。

**L4.2 项目重要层 —— 持久知识（慢衰减，importance 0.55~0.75）**
- **项目定位**：干嘛的、目标 / 范围 / 技术栈大方向 / 关键约束——提炼出"开工前必须先知道的那句话"。
- **架构 / 模块心智地图**：主要模块各干嘛、怎么协作、非显然的职责划分与"为什么这么分"。**是提炼出的心智模型，不是 `ls` 目录罗列**——哪个逻辑在哪个文件，用 `--pointer-ref` 指过去，别把目录树塞进 cue。
- **已定型 / 已辩论的决策**：哪些方案**讨论过几轮、改过、定了 X、否了 Y/Z 及原因**。**专治"后续会话又把已否决的方案重新拿出来讨论"**。

**L4.3 项目普通层 —— 快衰减层（importance 0.3~0.5）**
- **落这里的是"重要度低、时效短"的记忆**：典型如短命的进度开口（「还欠什么、下一步要做什么」——蔡格尼克效应，让任意新会话无缝接力）、临时状态、短命话题。**层级不绑定内容类型**：同是开口，短命的 importance 低、落这里快衰减自然翻篇；**重要的长期开口按其重要度落更高层**（如关键的长期开口 → L4.2）。
- **清理纪律**：发现**已完成 / 已失效的短期开口类记忆**（多在低层，但**不限定层级**）→ **核实 ground truth 后用 `engram forget --id <id>` 物理删除**（不堆历史、不留 superseded/tombstone 痕迹）。`forget` 语义 = 按 id 把记忆从库里物理移除。**删除前必核 ground truth**：凡删除理由涉及「已完成 / 已发布 / 已修复」，必须先核实 ground truth——查 git tag / log / 对应 commit、GitHub release、或实际代码 / 文件是否真的落地存在；绝不能只凭记忆条目自述「已完成 / 已发版」，也不能用一条记忆去推断另一条的状态（记忆会随版本过时，自述往往是写入当时的旧状态）。核实无误才可 forget；拿不准就保留、不删。

> **冷启动**：新项目 L4 一开始是空的。别靠引擎扫描灌库（那是"什么都往里记"的反面教材、且重复 artifact）。正确做法：首次实质会话里，主 agent 把上面 L4.1/L4.2 的定位 / 架构 / 铁律**提炼几条锚点**写下来（或用户显式"记住"），之后随使用增量补全。`claude init` 那种全项目扫描是"生成 CLAUDE.md"——是另一套机制，engram 存的是**它的补集**。

### override：用户显式"记住 X"
**只 override ①闸门 → 保证写入**；但**落哪层、给多高 importance 仍按 ②③ 判定，④敏感信息闸门永不豁免**（凭据只记位置不记值）。"记住"= "别忘了写下来"，**不等于"这是核心身份"——不要因此直接塞进 L1，也不要把 importance 一律拉满**。

**映射到层级 / importance：**
- **L1（潜意识层，上限极小 ~7 条，极难进）**：仅限**核心身份 / 长期全局偏好**——用户是谁、怎么称呼、说什么语言、雷打不动的全局规矩。importance 0.85~1.0。**普通"记一下"的事不进 L1；拿不准就放 L2。**
- **L2（重要、跨场景复用）**：importance 0.55~0.8。
- **L3（一般、易忘）**：importance 0.0~0.4。
- **项目 L4.1/L4.2/L4.3**：所有"仅本项目"的记忆（按 ② 判定）落此，必须带 `--project NAME` 且该项目库已挂载；L4 内部再按**重要度与时效**分 .1/.2/.3（不绑定内容类型）。

写入命令：
```
engram write --general-db G [--project-db n=p ...] \
  --level L3 --cue "一句话总结" \
  [--project NAME] [--importance 0.3] [--pinned] \
  [--pointer-kind file --pointer-ref "src/x.rs:42"] \
  [--tags intent,decision]
```
**cue 要写成"线索"**：一句话点出是什么 + 足够将来据以回想和检索的特征词；细节交给指针。

## 3. 会话末：巩固（复盘者，独立视角）

巩固由**独立的复盘者**做（不是干活的 agent 自己，避免自评注水）。复盘者**读会话转录（transcript）**回顾整场，按下面四步操作引擎。

### 3.1 判定"真使用"（决定加固谁）
真使用 = **影响了输出**的取用，分四档，只认第 3 档（它有 3a / 3b 两条通路，**两条都要打**）：
| 档 | 含义 | 算不算 |
|----|------|--------|
| 1 | 被加载进上下文（含每轮注入的热索引行） | ✗（在场 ≠ 用过） |
| 2 | 被 `recall` 取出但没派上用场 | ✗ |
| **3a** | **本次注入里实际出现的 L1/L2/L4.1/L4.2 行，真的左右了某个动作/回答** | **✓ → `confirm-use`** |
| **3b** | **经 `recall` 取出、且真的影响了输出**（引了它的结论 / 按它改了做法 / 据它否掉某方案 / 据它决定不再写副本） | **✓ → `confirm-use`** |
| 4 | 带来成功结果 | 不归因（太滞后） |

**铁律：与"被加载"解耦**——一条常驻 L1、每轮都被加载却没真正影响输出的记忆，也不该被加固。

**但反过来也要注意**：真使用**不限于显式 `recall`**——**本次注入里实际出现的那些 L1/L2/L4.1/L4.2 行**，被真正采纳的（第 3a 档）**必须加固**；反过来，**经 `recall` 取出、并真的影响了输出的条目（第 3b 档）同样必须加固**——L3 / L4.3 已退出常驻（见 §1「读」），`recall` 是它们**唯一**的加固通路，漏打就是判这两层常年零加固、单调衰减成僵尸带。

**⚠ 转录里的热索引 ≠ 干活的 agent 见过的热索引**：宿主对注入文本有硬上限（Claude Code 为 10000 字符），超出部分在进入 agent 上下文前就被截掉了，而转录里可能仍留着完整原文。**记忆出现在转录的热索引段里 ≠ 它被用过，甚至 ≠ agent 看见过它**——判据只有一个：agent 的**输出**里是否真的体现了这条记忆。

从转录里挑出第 3 档的记忆（注入热索引的行首带 `#<id首段>` 标记，据它到 `list --json` 里按 `mem-<标记>-...` 前缀锁定完整 id；`recall` 的候选本就带完整 id，直接用），加固：
```
engram confirm-use --general-db G [--project-db n=p ...] --ids id1,id2,...
```
（confirm-use 会追加真使用时间戳；若该记忆在冷库，会复活成 active。）

### 3.2 纠错（superseded 硬拽）
转录里若出现"旧记忆被新信息推翻"：
```
engram supersede --general-db G [--project-db n=p ...] --id <旧> --by <新>
```
这会无视层级/floor 把旧记忆移出热层（转 superseded，留负知识痕迹）。**这是唯一能把错误从 L1 拽出来的手段。**

### 3.2b 改写 cue（内容没错、只是 cue 写太长）

`supersede` 是给**内容被推翻**用的。若一条记忆内容仍然成立、只是当初把整段结论塞进了 cue（违反「cue 是一句话检索线索」），用 `reword` **原地改**：

```
engram reword --general-db G [--project-db n=p ...] --id <id>   --cue "收成一句话的检索线索" --pointer-detail "从 cue 里搬出来的细节正文"
```

**它只改 cue / pointer，`access_log`（使用历史）、`created_at`、层级、importance、pinned、status、tags 全部原样保留**——这正是它存在的理由：`write --overwrite` 和「write 新条 + supersede 旧条」都会把加固历史清零，那等于让「守 cue 纪律」和「保住加固资产」二选一。**改写超长 cue 一律走 `reword`，别走 write+supersede。**

写 cue 时记住：超过约 240 字符 engram 会警告并算给你看它占了该层字符预算的百分之多少。cue 越长，consolidate 装箱时越容易轮到它装不下而被下推一层，并压缩同层其它记忆的额度——细节放 `--pointer-detail`，不占热索引。

### 3.3 合并（一簇相关记忆冷掉时，并成粗 gist）
```
engram merge --general-db G [--project-db n=p ...] \
  --from id1,id2,id3 --cue "合并后的粗总结" [--level L2] [--importance 0.6]
```
源会转 tombstone（负知识），新记忆继承并集的访问历史。**让"实例"死、"schema"活。**

### 3.4 写入新记忆 + 升降级
- 按 §2 salience 判定，对达标的新知识 `engram write`（**写前先按第 ① 查重闸门 `recall` 查同事实**，命中改走 confirm-use/supersede，别写副本）。
- 升降级状态机（按 effective + 容量 + 迟滞自动升/降/淘汰）**已由收尾的 `consolidate-done` 确定性自动执行**，无需手动跑；仅想预览变迁时可选：
  ```
  engram consolidate --general-db G [--project-db n=p ...] --dry-run   # 仅预览，不写回
  ```

### 3.5（可选）回收
冷库/墓碑过期的硬删除（默认 cold 180 天、tombstone 3650 天；任何 recall→confirm-use 会重置计时）：
```
engram gc --general-db G [--project-db n=p ...] [--dry-run]
```

## 4. 命令速查

| 命令 | 用途 |
|------|------|
| `render` | 渲染热索引**全文**（不限预算、含 L3/L4.3 正文），供人工核对；hook 注入实际走 `hot-index`，那条路只出常驻四层 |
| `recall --query` | 词法检索冷/热库返候选（不写库） |
| `write` | 新建记忆（按 §2 落层） |
| `confirm-use --ids` | 把候选确认为真使用 → 加固 / 复活 |
| `supersede --id --by` | 纠错硬拽 |
| `merge --from --cue` | 合并一簇为粗 gist |
| `consolidate` | 升降级 / 淘汰状态机（`--dry-run` 预览） |
| `forget --id` | 按 id 物理删除一条记忆（不留 tombstone；已完成 / 已失效的短期开口类记忆核实 ground truth 后用它删，不限定层级） |
| `gc` | TTL 硬删除（`--dry-run` 预览） |
| `list` | 可读检视（redb 是二进制，用它看内容） |
| `import --from-json-dir` | 从 JSON 目录导入（迁移/灌库用） |
| `resolve --format json\|env` | 按 `.engram/` 锚点解析当前作用域（general/project 库路径 + name + kind），手动跑读写命令前先来一次 |
| `root --project-dir D` | 把 D 设为项目管理目录（防嵌套 + 建 `.engram/workspace` 标记与管理库 + 写 L2 登记） |
| `serve [--open] [--port N]` | 起本地网页看板，浏览**本机全部记忆**（公共库 + 扫描到的所有项目库）；见下「网页看板」 |

> 检视任何库内容：先 `engram resolve --format json` 拿到库路径，再 `engram list --general-db G --project-db n=p --status all`

### 网页看板（用户想在浏览器里看记忆时）

当用户说「**我要在网页端/浏览器里看记忆**」「打开记忆看板」这类意图时，**在后台**起看板服务并让它自动开浏览器（`serve` 是常驻进程，务必后台运行、别阻塞会话）：

```bash
engram serve --open
```

它从 `.engram/` 锚点向上找项目管理目录 → 扫其下所有子项目库 + 公共库 → 起本地 HTTP（默认 `http://127.0.0.1:8765/`）→ 开浏览器。端口被占（已在跑）会幂等复用。起好后把地址告诉用户，并说明页面右上角有「停止服务」按钮。Claude Code 插件下等价的 slash 命令是 `/engram web`。
